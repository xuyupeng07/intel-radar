# 行业情报雷达 · 竞品与对标调研（2026-10）

> 用途：为 [PRD](./PRD-行业情报雷达.md) 提供外部参照，回答两个问题——**别人做到哪了**、**我们还能补什么**。
> 口径：2026-10-28 检索官网与公开资料；**产品能力以官网当期口径为准，价格除注明外均为「无公开定价、需询价」**。标注「待核实」的条目请在调研时二次确认。
> 阅读顺序建议：§1 结论 → §9 可集成功能清单 → §11 调研路线 → §12 链接总表。

---

## 1. 结论先行（5 条）

1. **市场分成两类，中间是空的**：国际产品（Feedly / AlphaSense / Crayon / Klue）强在「工作流与协作」，国内产品（识微 / 鹰眼 / 慧科）强在「数据源覆盖与合规资质」，但**没有一个把「搜索 API 可插拔 + 可审核日报 + 企微/钉钉/飞书分发」做成一个轻量产品**。
2. **国际产品普遍不接中国 IM**。Feedly、Meltwater、Crayon 的分发是 Email / Slack / Teams，企微、钉钉、飞书基本没有官方集成。这是最直接的差异化空位。
3. **国内舆情 SaaS 的数据是封闭的**。卖的是「我们的库 + 我们的报告」，用户不能自己接博查/秘塔/DeepSeek 这类搜索 API，也不能按自己的主题逻辑改采集。我们反过来做「编排层」，正好错位。
4. **AI 搜索产品（Perplexity / 秘塔 / 元宝）解决「这一次查」，不解决「每天替我盯着」**。它们不沉淀、不主动推送、没有审核，也没有团队视角。我们要补的是「持续性与可运营性」。
5. **开源侧只有零件，没有成品**：RSSHub 解决「源」，Huginn / changedetection.io 解决「监控」，n8n / Dify 解决「编排」，但没人把「去重聚类 + 日报 + 审核 + 多 IM 分发」打包好。`intel-briefing` 最接近，但它是个人向脚本，没有多渠道与审核。

## 3. A 层：国际 AI 情报 / 舆情平台

### 3.1 Feedly — <https://feedly.com>

- **定位**：从 RSS 阅读器长成的 AI 情报平台，主打「Market Intelligence」：按主题/公司/技术追踪，AI（Leo）做摘要与趋势聚类。
- **可借鉴**：① 主题（Topic）模型非常成熟，支持「公司 / 行业 / 技术 / 关键词」四类；② AI 摘要与「为什么重要」；③ Newsletter 式日报；④ 团队共享与 Slack/Teams 集成。
- **差距（我们的机会）**：中文源覆盖弱；不接企微/钉钉/飞书；不能自带搜索 API；企业版价格不透明。
- **调研重点**：看它的 Topic 配置界面与「AI Feed」的信息密度，这是我们要对标的交互基线。

### 3.2 AlphaSense — <https://www.alpha-sense.com>

- **定位**：企业级「决策级 AI」市场情报，聚合券商研报、财报、电话会、新闻、专家访谈，面向投研/咨询/企业战略。
- **可借鉴**：① 文档级引用与「跳到原文第几页」的溯源体验；② 多文档对比与要点抽取；③ 企业级权限与合规。
- **差距**：重、贵、实施周期长；不适合「每天早上一份轻日报」的场景。
- **调研重点**：它的「引用 + 原文定位」交互，是我们 FR-05 可信度的上限参照。

### 3.3 Meltwater — <https://www.meltwater.com>

- **定位**：媒体与社媒监测老牌厂商，覆盖新闻、社交、广播、播客，提供日报/周报与预警。
- **可借鉴**：① 报告模板与「品牌健康度」指标；② 预警规则配置；③ 多语言。
- **差距**：中文社媒覆盖有限；IM 只到 Slack/Teams；按年报价。
- **调研重点**：它的「Report Builder」——板块可拖拽、可定时发送，正是我们 FR-06 的产品化方向。

### 3.4 Brandwatch — <https://www.brandwatch.com>

- **定位**：社媒聆听与消费者洞察（Cision 旗下），强在社交数据量与情感分析、图像识别。
- **可借鉴**：① 查询语法（复杂布尔 + 排除）；② 情感与话题聚类可视化。
- **差距**：偏「消费者/品牌」，不偏「行业研究」；无中文 IM。

### 3.5 Signal AI — <https://signal-ai.com>

- **定位**：媒体情报 + 声誉与风险监测，主打语义搜索（Search 2.0）与「AI 简报」。
- **可借鉴**：① 语义检索而非关键词匹配；② 风险信号分级；③ 面向 PR/传播的日报。
- **调研重点**：Search 2.0 的查询理解，可作为我们「关键词 → 自然语言查询」的参考。

### 3.6 Dataminr — <https://www.dataminr.com>

- **定位**：实时事件检测，从公开数据中比新闻更早发现突发事件，面向企业安全与风控。
- **可借鉴**：① 「早于新闻」的时效追求（对应我们 S2 预警场景）；② 事件分级与置信度。
- **差距**：极贵、面向大企业；不做日报编辑流。

### 3.7 Crayon — <https://www.crayon.co>

- **定位**：竞品情报（CI）平台，自动追踪竞品官网、定价页、招聘、评论、社媒，产出 Battlecard。
- **可借鉴**：① **网页变更监控**（我们 FR 目前缺失，见 §9 P1-1）；② Battlecard 形态（销售场景）；③ 已推出 CI MCP Server，把情报能力暴露给 AI 客户端。
- **调研重点**：「竞品官网变更 → 自动告警」这条链路，是我们最容易补的高价值功能。

### 3.8 Klue — <https://klue.com>

- **定位**：竞品情报 + 销售赋能，把情报嵌进 CRM 与 Slack，让销售在客户会议前拿到 Battlecard。
- **可借鉴**：① 情报与「使用场景」绑定，而不是堆在仪表盘；② 与 IM/CRM 的深度集成。
- **差距**：不覆盖中文源；不做日报分发到企微。

## 4. B 层：国内舆情与媒体监测

### 4.1 识微科技 — <https://www.civiw.com>

- **定位**：企业舆情监测 SaaS，全网监测 + 负面预警 + 日报/周报 + 竞品监测。
- **可借鉴**：① 面向企业的「监测方案」打包方式（关键词组 + 平台范围 + 报告频次）；② 预警到人的链路；③ 报告模板。
- **差距**：数据封闭，不能自带搜索源；偏声誉管理，不贴行业研究。

### 4.2 鹰眼速读网（蚁坊软件）— <https://www.eefung.com>

- **定位**：政府/企业舆情监测与研判，全网监测、早发现、态势分析、专题报告。
- **可借鉴**：① 「早发现」的时效指标；② 研判报告的写法（事件脉络 + 传播路径 + 建议）。
- **差距**：项目制交付，重人工；无开放 API 生态。

### 4.3 慧科讯业 Wisers — <https://www.wisers.com.cn>

- **定位**：大中华区老牌媒体监测，覆盖报刊、网媒、社媒，做 AI 数据平台与传播分析。
- **可借鉴**：① 媒体源治理（版权、去重、转载链）；② 传播效果报告。
- **差距**：传统 SaaS 交互，AI 能力偏「分析」而非「生成」。

### 4.4 清博 — <https://www.gsdata.cn>

- **定位**：新媒体大数据与舆情，指数、榜单、开放平台 API。
- **可借鉴**：① 指数化（热度/影响力）思路，可用于我们「重要性打分」；② 有 API 开放平台，可作为数据源候选。
- **调研重点**：开放平台的 API 清单与计费，判断能否作为 Provider 接入。

### 4.5 微热点 — <https://www.wrd.cn>

- **定位**：微博舆情起家，热度指数、传播分析、舆情 APP。
- **可借鉴**：热点发现与传播路径；免费入口可作体验参考。

### 4.6 知微数据 — <https://www.zhiweidata.com>

- **定位**：舆情与声誉风险管理，事件分析、传播研究。
- **可借鉴**：事件级分析框架（起因—发酵—峰值—消退），可用于「事件续报」。

### 4.7 新榜 — <https://www.newrank.cn>

- **定位**：内容与新媒体数据，公众号/视频号榜单、投放监测。
- **可借鉴**：KOL/内容账号维度的监测，是我们「社媒信号」的合规替代（不直接爬公众号）。

|---|---|---|---|
| 财联社 | 7×24 电报 + 精选 | 短讯格式：时间 + 一句话 + 影响 | <https://www.cls.cn> |

## 9. 还能集成哪些功能（按价值 / 成本排序）

### 9.1 P0 —— 首版就该有（已被竞品验证是刚需）

| # | 功能 | 谁在证明它 | 价值 | 成本 |
|---|---|---|---|---|
| 1 | **来源溯源卡片**：每条情报展示首发媒体、首发时间、其他转载源 | AlphaSense / Feedly | 建立信任，直接决定用户敢不敢用 | 低 |
| 2 | **多 Provider 降级链**：主源挂了自动切备源 | 无（我们的差异） | 稳定性 | 低 |
| 3 | **成本看板**：按日/主题/Provider 拆账 | 无（普遍缺失） | 可运营 | 低 |
| 4 | **「今日必读」Top3**：不是按时间，而是按重要性 | 财联社 / 36 氪早报 | 决定打开率 | 中 |
| 5 | **测试发送 + 幂等**：避免重复刷群 | 无（普遍踩坑） | 减少事故 | 低 |

### 9.2 P1 —— 第二版补齐（差异化来源）

## 10. 定价锚点（仅列可公开核实的）

| 项 | 口径 | 来源 |
|---|---|---|
| DeepSeek Search / Fetch | **$0.75 / 1000 次成功请求**；Search 100 QPS、Fetch 25 QPS；失败与空结果不计费 | [官方文档](https://api-docs.deepseek.com/guides/search/) |
| 秘塔搜索 API | 上线时公开口径约 **0.03 元/次起**（多模态/深度搜索可能更高） | [报道](https://m.chinaz.com/ainews/19928.shtml) |
| 博查搜索 API | 按次计费，具体档位在开放平台查看 | [开放平台](https://open.bochaai.com) |
| Tavily | 按 credit 计费，有免费额度 | [官方文档](https://docs.tavily.com/documentation/api-credits) |
| Feedly / AlphaSense / Meltwater / Brandwatch / Crayon / Klue | **无公开定价，销售询价**（企业年费制） | 官网 |
| 识微 / 鹰眼 / 慧科 / 清博 | **无公开定价，按监测方案报价** | 官网 |

> 结论：**搜索 API 这一层已经很便宜**（单次 0.005–0.03 元），系统的成本大头会落在「模型调用」和「人工审核时间」，而不是搜索费。这支持我们在 PRD §10 的成本估算。

## 11. 我们的定位

```text
                 工作流深度（审核 / 协作 / 分发）
                              ▲
                              │
        AlphaSense ●          │          ● Klue / Crayon
        Meltwater  ●          │
                              │        ★ 我们：搜索可插拔 + 可审核日报 + 中国 IM
                              │
        识微 / 鹰眼 ●──────────┼──────────● Feedly
                              │
        RSSHub / Huginn ●     │      ● Perplexity / 秘塔
                              │
                              └──────────────────────────►
                                        数据源广度（可自带 API）
```

**一句话定位**：在「数据源可自带」和「工作流可审核」之间，做一个**轻、可自建、IM 原生**的中间层。

**三条护城河（可积累的）**

1. **Provider 适配器库**：接得越多、越稳，迁移成本越高。
2. **主题模板库**：行业预置关键词/实体/信源包（半导体、医药、新能源…），新用户 10 分钟可用。
3. **评测集**：真实反馈沉淀出的「什么算好日报」，是提示词与阈值的护城河。
